Orquestrador Logístico Omnichannel · Pittol Calçados

✅ Status: Em Produção · Sistema operando nas 28 filiais da rede · Pittol Calçados.

Desenvolvimento e arquitetura de um orquestrador logístico omnichannel de ponta a ponta para conectar a operação central de e-commerce a 28 filiais. O sistema automatizou todo o ciclo de vida do pedido, substituindo rotinas manuais por um ecossistema digital integrado e de alta performance, atuando desde a triagem até a expedição e o controle financeiro.

🌪️ O Cenário (Antes)

Operação de e-commerce 100% manual: pedidos distribuídos por planilhas, checklists de separação em papel, integração com Correios via portal manual e rateio financeiro feito no Excel, consumindo horas da gerência logística.

🚀 A Solução (Depois)

Ecossistema digital completo: roteamento inteligente de pedidos por estoque, picking digital auditável, geração automática de etiquetas via API dos Correios e motor de rateio por leitura de XML de NF-e.

📦 Integração Logística e Despacho
  • Integração nativa com API dos Correios: Geração automática de etiquetas de postagem e rastreamento em tempo real, eliminando o acesso manual ao portal dos Correios.
  • Módulo de Impressão Simplificada (Baixa Nota): Unificação da emissão de etiqueta de postagem + nota fiscal em um único fluxo ágil para as lojas, reduzindo drasticamente o tempo de expedição na ponta.
✅ Digitalização do Picking
  • Checklist de Separação Digital: Substituiu as listas de papel por um fluxo digital completo e à prova de erros. A separação de mercadorias é rápida, auditável e padronizada nas 28 filiais.
  • Resultado direto: Redução a quase zero dos erros de envio de mercadorias trocadas, impactando positivamente a satisfação do cliente final e evitando custos de devolução.
💰 Inteligência Financeira e Rateio
  • Motor de Processamento de XML (NF-e): O sistema lê e extrai automaticamente as informações das Notas Fiscais em formato XML, sem intervenção humana.
  • Rateio Automático Exato: Distribuição precisa de custos e receitas entre o e-commerce central e as 28 lojas físicas, eliminando as horas de trabalho manual do gerente logístico no fechamento mensal.
🗺️ Roteamento Inteligente (Dark Store)
  • Algoritmo de Distribuição por Estoque: Direciona cada pedido online para a filial ideal com base no estoque disponível, transformando as 28 lojas físicas em mini-centros de distribuição.
  • Descentralização Logística: A operação de e-commerce deixou de depender de um único ponto central, ganhando resiliência e capacidade de escala sem aumento de custo fixo.

Arquitetura de Dados & Sistema de Metas

Este projeto nasceu de uma necessidade crítica: a diretoria precisava cruzar as Vendas (do ERP) com as Metas (definidas pelos gerentes) em tempo real. O desafio? O Power BI não permite entrada de dados e consultas diretas estavam derrubando a performance do banco de produção.

📌 Status: Projeto Entregue e Validado (Tecnicamente).
A arquitetura solucionou os problemas de "Lock" no banco Oracle e habilitou o input de metas. A implementação em todas as 28 lojas aguarda priorização estratégica, servindo hoje como case de arquitetura híbrida na empresa.

🚫 O Gargalo (Oracle Lock)

Conectar o BI direto no ERP Oracle gerava concorrência de I/O. Relatórios pesados rodando no horário comercial causavam lentidão no checkout (PDV) das lojas, impactando a venda na ponta.

💡 A Sacada (Write-back)

Como o Power BI é "apenas leitura", desenvolvi uma aplicação satélite (PHP) para Input de Metas. O sistema valida os valores e os injeta no Data Warehouse, onde são cruzados automaticamente com as vendas.

Arquitetura de Dados Implementada
  • Data Warehouse Intermediário (MySQL): Criei uma camada de dados isolada. O BI bate aqui, nunca na produção. Resultado: Zero impacto na operação das lojas.
  • Pipeline ETL (Pentaho): Rotinas automatizadas que extraem dados de vendas, tratam inconsistências e carregam o DW incrementalmente (D-1).
  • Integração Híbrida: O sistema combina dados legados (Oracle On-Premise) com dados novos de metas (App Web) em um dashboard unificado na nuvem.

PsiAssist - SaaS Financeiro

O PsiAssist é uma plataforma SaaS onde a integridade dos dados não é negociável. Diferente de aplicações comuns que delegam toda a lógica para o Backend (PHP), este projeto adota uma arquitetura Database-First para blindar as regras de negócio financeiras.

💥 O Risco (Inconsistência)

Em sistemas distribuídos, falhas de rede ou no servidor de aplicação podem deixar dados "órfãos" (ex: um agendamento concluído sem a respectiva fatura gerada), causando prejuízo financeiro.

🛡️ A Solução (ACID)

Encapsulamento de regras críticas em Stored Procedures. Isso garante transações atômicas: ou o agendamento finaliza E a fatura é criada, ou nenhuma das duas ações ocorre.

Engenharia de Software Aplicada
  • Integração Orientada a Eventos (Webhooks): O sistema processa pagamentos do Mercado Pago de forma assíncrona. O script PHP recebe o payload JSON, valida a assinatura de segurança e aciona a baixa automática no banco.
  • Modelagem Relacional (3NF): Banco de dados normalizado para suportar múltiplas clínicas (Tenants) com segurança e isolamento de dados.
  • Full Stack Financeiro: Fluxo completo implementado, desde a geração do Pix/Boleto na API até a conciliação bancária automática.

Portal de Governança & Utilitários

Antes deste projeto, a manutenção de dados críticos (como SPED e NCM) dependia de scripts descentralizados ou intervenção direta da TI. Criei este Portal Corporativo para centralizar essas ferramentas, mitigando riscos de segurança e o fenômeno de "Shadow IT".

🔒 O Problema (Risco)

Ferramentas de manutenção rodando localmente nas máquinas dos usuários dificultam a auditoria e aumentam o risco de execução acidental de processos críticos por pessoas não autorizadas.

🛡️ A Solução (Governança)

Desenvolvimento de uma interface Web segura que atua como uma camada de abstração. O usuário não acessa o banco ou o script direto; ele interage com o Portal, que valida as permissões e executa a tarefa de forma controlada.

Pilares de Segurança Implementados
  • RBAC (Role-Based Access Control): Implementação rigorosa de Segregação de Funções. O setor Fiscal vê apenas ferramentas do SPED; Compras vê apenas NCM. O Admin gerencia tudo.
  • Self-Service IT: Empoderamento dos usuários chaves. Eles ganham autonomia para resolver problemas rotineiros sem abrir chamados, reduzindo o SLA da TI.
  • Auditoria & Logs: Cada ação executada no portal fica registrada (quem fez, quando fez e o que alterou), garantindo rastreabilidade.

Automação de Ingestão de Dados (ETL)

Este projeto transformou uma rotina manual e propensa a falhas em um Pipeline de Dados Automatizado. O objetivo era resolver o gargalo na conferência de faturas logísticas, permitindo que o setor financeiro auditasse custos de frete em escala.

🌪️ O Desafio (Dados "Sujos")

Os relatórios CSV dos Correios não são tabulares perfeitos: misturam cabeçalhos, rodapés e agrupamentos no mesmo arquivo. Tratar isso no Excel era inviável para milhares de linhas.

⚙️ Engenharia (Custom Parser)

Desenvolvimento de um script PHP robusto que atua como uma "State Machine". Ele lê o arquivo linha a linha, identifica contextos (cabeçalho vs. dados), sanitiza valores monetários (BRL para Decimal) e normaliza para o banco.

Impacto Real
  • Ganho de Produtividade: O processo de conferência caiu de horas (manuais) para segundos (automático).
  • Auditoria Financeira: Com os dados estruturados no banco, o sistema cruza automaticamente o Valor Cobrado vs. Tabela de Contrato, alertando divergências de frete.
  • Qualidade de Dados: Eliminação de erros humanos de digitação na entrada de dados financeiros.

Agente SQL com AI (Segurança em Foco)

Este projeto foi desenvolvido como uma Prova de Conceito (PoC) para explorar o potencial da IA Generativa na democratização de dados, utilizando um middleware em Python para traduzir perguntas naturais em SQL.

🚫 O Risco (Desafio)

Conectar uma IA diretamente ao banco de produção (ERP) é perigoso. Queries mal otimizadas geradas pela IA poderiam travar a operação da empresa, além do risco de "alucinações" nos dados.

🛡️ Solução "Zero-Risk"

Implementação de uma arquitetura de camadas. A IA consulta um Data Mart isolado (banco espelho), garantindo que a produção nunca seja impactada, mesmo se a query for pesada.

Engenharia do Middleware (Python)
  • Sanitização de Queries: O script Python atua como um "firewall", recebendo a intenção do usuário, enviando o schema para a OpenAI e validando a query SQL retornada antes da execução.
  • Pipeline de Dados: O Data Mart consultado pela IA é alimentado por um processo de ETL (Pentaho) que roda a cada 30 minutos, garantindo dados frescos sem concorrência com o ERP.
  • Prompt Engineering: Contexto otimizado para que o modelo entenda as regras de negócio específicas da empresa (ex: cálculo de margem e impostos).
📉 Análise de Viabilidade & Conclusão

Após a fase de curadoria de dados, o projeto foi classificado como não apto para produção.

  • O Motivo: A alta complexidade da modelagem e as regras de negócio específicas (ex: impostos, devoluções parciais) levaram o modelo a gerar queries sintaticamente corretas, mas semanticamente imprecisas.
  • O Resultado: Os números apresentados divergiam dos relatórios oficiais (BI).
  • Decisão de Engenharia: Priorizando a integridade da informação, optamos por manter o BI tradicional (Dashboards) em vez de arriscar decisões baseadas em alucinações da IA.

Modelagem de Dados Complexa

Este projeto de Engenharia Reversa foi desenvolvido para superar limitações de softwares de prateleira. O objetivo era criar um ERP Agropecuário capaz de gerenciar não apenas o financeiro, mas o ciclo biológico completo do rebanho.

🎯 O Desafio

Modelar eventos assíncronos e interdependentes. Exemplo: Um animal não pode ser vendido se tiver registro sanitário pendente (vacina/carência). O sistema precisava garantir essa consistência via banco de dados.

🛠️ Solução (Data Engineering)

Desenvolvimento de um modelo relacional altamente normalizado (3NF) cobrindo mais de 30 entidades. Uso rigoroso de chaves estrangeiras e constraints para impedir "dados órfãos" ou inconsistências biológicas.

Destaques da Modelagem
  • Rastreabilidade Total: Histórico genealógico (árvore familiar) e sanitário vinculado ao brinco do animal.
  • Integridade Referencial: O modelo impede a exclusão acidental de registros que possuem histórico financeiro ou reprodutivo.
  • Escalabilidade: Estrutura preparada para suportar milhares de animais e movimentações diárias sem perda de performance.
